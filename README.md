# Лабораторная работа №3

## Веб-сервис расчёта нагрузки на электросеть при одновременном включении приборов

### Цель работы

Создание веб-сервиса в backend-части системы для дальнейшего использования в SPA.

В рамках лабораторной работы реализован REST API для работы с электрическими приборами, пользователями и лайками. Веб-сервис взаимодействует с базой данных PostgreSQL через ORM GORM. Изображения и короткие видео электрических приборов хранятся в MinIO.

Все методы API имеют префикс:

```text
/api
```

В лабораторной работе №3 полноценная авторизация ещё не реализована. Текущий пользователь фиксирован и имеет идентификатор `1`. Его идентификатор получается через функцию-singleton.

Для электрического прибора предусмотрены статусы:

- `черновик`;
- `опубликован`;
- `удален`.

Допустимый переход статусов:

```text
черновик -> опубликован -> удален
```

Вернуть опубликованную запись обратно в статус `черновик` нельзя.

Удаление является логическим: запись остаётся в базе данных со статусом `удален`, но больше не передаётся клиенту.

## HTTP-методы

### Домен электрических приборов

#### Получение списка опубликованных электрических приборов

```http
GET /api/electricity_consumers
```

Метод возвращает список электрических приборов со статусом `опубликован`.

Поддерживается фильтрация по мощности с помощью query-параметров:

```text
min_power
max_power
```

Пример запроса:

```http
GET /api/electricity_consumers?min_power=1&max_power=3
```

Для каждого электрического прибора возвращается признак `is_creator`:

- `1` — текущий пользователь является создателем;
- `0` — текущий пользователь не является создателем.

Записи со статусами `черновик` и `удален` в список не передаются.

---

#### Получение ленты опубликованных электрических приборов

```http
GET /api/electricity_consumers/feed
```

Метод возвращает опубликованный электрический прибор из ленты.

Для получения следующего опубликованного прибора используется идентификатор текущего прибора и параметр `next=true`:

```http
GET /api/electricity_consumers/feed/:id?next=true
```

Пример:

```http
GET /api/electricity_consumers/feed/3?next=true
```

В ленту передаются только записи со статусом `опубликован`.

---

#### Получение черновика текущего пользователя

```http
GET /api/electricity_consumers/draft
```

Метод возвращает черновик текущего пользователя.

Идентификатор черновика в URL не передаётся.

Для одного пользователя может существовать не более одного черновика.

---

#### Добавление электрического прибора

```http
POST /api/electricity_consumers
```

Метод создаёт новую запись электрического прибора в статусе `черновик`.

Данные передаются в формате:

```text
multipart/form-data
```

Передаваемые поля:

| Поле | Описание |
|---|---|
| `name` | Название электрического прибора |
| `image` | Файл изображения |
| `video` | Файл короткого видео |

Изображение и видео передаются как файлы.

Файлы сохраняются в MinIO. Для них генерируются новые имена на латинице, а в базе данных сохраняются сгенерированные имена файлов.

Создатель и дата создания определяются на backend и не передаются клиентом.

---

#### Публикация электрического прибора

```http
PUT /api/electricity_consumers/:id
```

Пример:

```http
PUT /api/electricity_consumers/13
```

Пример тела запроса:

```json
{
  "description": "Описание электрического прибора",
  "power_kw": 2.2
}
```

При публикации выполняются следующие действия:

- проверяется, что черновик принадлежит текущему пользователю;
- статус изменяется с `черновик` на `опубликован`;
- сохраняется описание;
- сохраняется мощность;
- рассчитывается сила тока;
- устанавливается дата формирования.

Сила тока рассчитывается на backend по формуле:

```text
I = P * 1000 / 220
```

где:

- `I` — сила тока, А;
- `P` — мощность прибора, кВт;
- `220` — напряжение сети, В.

Системные поля клиентом не изменяются.

---

#### Логическое удаление электрического прибора

```http
DELETE /api/electricity_consumers/:id
```

Пример:

```http
DELETE /api/electricity_consumers/13
```

Удалить можно только опубликованный электрический прибор, принадлежащий текущему пользователю.

Используется soft delete.

При удалении:

- запись физически остаётся в базе данных;
- статус изменяется на `удален`;
- устанавливается дата завершения.

Удалённые записи клиенту не передаются.

---

#### Установка или удаление лайка

```http
POST /api/electricity_consumers/:id/likes
```

Лайк устанавливается от имени текущего пользователя.

Для установки лайка передаётся:

```json
{
  "value": 1
}
```

Для удаления лайка:

```json
{
  "value": 0
}
```

Поле `value` может принимать только значения:

- `1` — установить лайк;
- `0` — удалить лайк.

Один пользователь не может поставить одному электрическому прибору несколько одинаковых лайков.

---

### Домен пользователя

#### Регистрация пользователя

```http
POST /api/users
```

Пример тела запроса:

```json
{
  "login": "milena",
  "password": "123456"
}
```

При успешном выполнении создаётся новая запись пользователя.

Логин пользователя должен быть уникальным.

---

#### Аутентификация пользователя

```http
POST /api/auth/login
```

Пример тела запроса:

```json
{
  "login": "milena",
  "password": "123456"
}
```

В лабораторной работе №3 метод является заглушкой.

Полноценная аутентификация будет реализована в лабораторной работе №4.

---

#### Деавторизация пользователя

```http
POST /api/auth/logout
```

В лабораторной работе №3 метод является заглушкой.

Полноценная деавторизация будет реализована в лабораторной работе №4.

## Системные поля

Системные поля электрического прибора нельзя передавать с клиента для произвольного изменения.

К системным полям относятся:

- `id`;
- `status`;
- `creator_id`;
- `date_create`;
- `date_formation`;
- `date_completion`.

Они устанавливаются и изменяются только на backend в соответствии с бизнес-логикой приложения.

В лабораторной работе №3 текущий пользователь фиксирован:

```text
currentUserID = 1
```

Доступ к идентификатору текущего пользователя выполняется через функцию-singleton.

## База данных

Для хранения данных используются три таблицы:

- `electricity_consumers`;
- `users`;
- `likes`.

### Таблица `electricity_consumers`

Хранит информацию об электрических приборах.

| Поле | Описание |
|---|---|
| `id` | Идентификатор электрического прибора |
| `name` | Название электрического прибора |
| `description` | Описание электрического прибора |
| `status` | Статус записи |
| `image` | Сгенерированное имя файла изображения в MinIO |
| `video` | Сгенерированное имя файла видео в MinIO |
| `power_kw` | Мощность электрического прибора, кВт |
| `current_a` | Рассчитанная сила тока, А |
| `date_create` | Дата создания записи |
| `creator_id` | Идентификатор пользователя-создателя |
| `date_formation` | Дата публикации записи |
| `date_completion` | Дата логического удаления записи |

Возможные значения поля `status`:

```text
черновик
опубликован
удален
```

Поле `creator_id` связано с таблицей `users`.

---

### Таблица `users`

Хранит данные пользователей.

| Поле | Описание |
|---|---|
| `id` | Идентификатор пользователя |
| `login` | Логин пользователя |
| `password` | Пароль пользователя |

Поле `login` является уникальным.

---

### Таблица `likes`

Хранит информацию о лайках электрических приборов.

| Поле | Описание |
|---|---|
| `id` | Идентификатор лайка |
| `user_id` | Идентификатор пользователя |
| `electricity_consumer_id` | Идентификатор электрического прибора |

Поле `user_id` связано с таблицей `users`.

Поле `electricity_consumer_id` связано с таблицей `electricity_consumers`.

Пара полей:

```text
user_id + electricity_consumer_id
```

является уникальной, поэтому один пользователь не может поставить одной услуге несколько одинаковых лайков.

---

## Хранение изображений и видео

Изображения и короткие видео электрических приборов хранятся в MinIO.

При добавлении нового электрического прибора backend:

1. получает изображение и видео через `multipart/form-data`;
2. проверяет тип переданных файлов;
3. генерирует новые имена файлов на латинице;
4. сохраняет файлы в MinIO;
5. сохраняет сгенерированные имена файлов в таблице `electricity_consumers`.
